# YaPhoto

![Python](https://img.shields.io/badge/python-3.10%2B-blue)
![Platforms](https://img.shields.io/badge/platform-Windows%20%7C%20Linux%20%7C%20macOS-lightgrey)
[![License: MIT](https://img.shields.io/badge/license-MIT-green)](LICENSE)

**Локальный архив фото и видео из безлимитной медиатеки Яндекс Диска.**

YaPhoto скачивает оригиналы из `/photounlim` на ваш диск, проверяет их по облачному
MD5 и ведёт каталог в SQLite. Работать можно из консоли или через локальную
веб-галерею. Файлы в облаке программа не изменяет: она только читает Диск.

> [!IMPORTANT]
> Это неофициальный клиент. Он использует веб-API Яндекс Диска, у которого нет
> стабильного публичного контракта, поэтому изменения на сайте могут потребовать
> обновления кода. Проект не связан с Яндексом.

## Возможности

- **Фото, видео или всё сразу**: обход безлимита `/photounlim`, тип медиа выбирается флагом `--media`.
- **Оригиналы без потерь**: исходные имена файлов и облачные даты, проверка размера и облачного MD5.
- **Контроль целостности**: для каждого файла сохраняется локальный SHA256, команда `verify` полностью пересчитывает хеши.
- **Возобновление работы**: уже проверенные копии повторно не скачиваются, а видео докачиваются через HTTP Range.
- **Параллельная загрузка**: от 1 до 32 воркеров, повторные попытки, живая цветная панель прогресса в консоли.
- **Запасной вариант**: если оригинал недоступен, сохраняется лучшее доступное превью. После успешной загрузки оригинала превью удаляется.
- **Веб-галерея**: фильтры, шкала дат, прогресс воркеров, локальные миниатюры и управление всеми операциями из браузера.
- **Отчёты**: журналы с ротацией, JSON-отчёты об ошибках и недостающих оригиналах, статистика серверов хранения.
- **Защита архива**: блокировка не даёт двум процессам одновременно менять один архив.

## Требования

- Python **3.10+**
- Windows, Linux или macOS
- Аккаунт Яндекс Диска с безлимитом для фото и видео
- Браузерное расширение для экспорта cookies в JSON, например [Cookie-Editor](https://cookie-editor.com/)

Runtime-зависимости зафиксированы с SHA256 в `requirements.lock`: `requests`,
`Pillow`, `pillow-heif` (для HEIC) и `imageio-ffmpeg` (для видео).

## Быстрый старт

### 1. Получите cookies

1. Откройте [disk.yandex.ru](https://disk.yandex.ru) в браузере и войдите в аккаунт.
2. Экспортируйте cookies через Cookie-Editor как **JSON-массив**.
3. Сохраните их в файл `cookies.json` рядом с `yaphoto.py`.

> [!WARNING]
> `cookies.json` даёт полный доступ к вашему аккаунту. Не коммитьте его, не
> прикладывайте к Issue и не показывайте на скриншотах. Подробнее в [SECURITY.md](SECURITY.md).

### 2. Установите и запустите

**Windows (PowerShell)**

```powershell
.\setup.bat
.\run.bat check                                      # проверить вход
.\run.bat scan --media photo                         # построить каталог
.\run.bat download --media photo --limit 20 --workers 2   # пробная загрузка
```

**Linux / macOS**

```sh
chmod +x setup.sh run.sh web.sh
./setup.sh
./run.sh check
./run.sh scan --media photo
./run.sh download --media photo --limit 20 --workers 2
```

Если пробная загрузка прошла успешно, уберите `--limit`, чтобы скачать всю медиатеку.
Скрипты сами создают `.venv` и устанавливают зависимости с проверкой хешей.

## Веб-галерея

```powershell
.\web.bat        # Windows
./web.sh         # Linux / macOS
```

Сервер слушает только `127.0.0.1:8765`, и браузер открывается автоматически по
ссылке входа с одноразовым секретом сеанса. С флагом `--no-browser` откройте
**полную** ссылку из консоли вручную. Адрес без действующего сеанса вернёт отказ в доступе.

Из галереи можно:

- загрузить cookies и проверить вход;
- запустить сканирование, скачивание, проверку файлов и улучшение превью;
- следить за прогрессом каждого воркера и за журналом;
- просматривать медиатеку по фильтрам («Оригиналы», «Превью», «Ошибки») и переходить по шкале дат.

Параметры `web.py`: `--output`, `--cookies`, `--port` (по умолчанию 8765), `--no-browser`.

## Команды CLI

```
run.bat <команда> [параметры]      # Windows
./run.sh <команда> [параметры]     # Linux / macOS
```

| Команда | Назначение |
| --- | --- |
| `check` | Проверить вход по cookies. Cookies и токены в консоль не выводятся. |
| `scan` | Просканировать медиатеку и обновить каталог. Перед `download` нужен завершённый scan. |
| `download` | Скачать недостающие файлы. Свежие ссылки на скачивание запрашиваются автоматически. |
| `verify` | Полностью пересчитать хеши локальных копий, без доступа к сети. |
| `status` | Показать сводку по каталогу. |
| `retry-failed` | Вернуть неудачные и отложенные файлы в очередь. |
| `rescue-previews` | Сохранить превью для фото с ошибкой или отложенных фото. |
| `upgrade-previews` | Заменить сохранённые превью более крупными вариантами, если они есть. |
| `normalize-previews` | Убрать префикс `##` у превью из архивов ранних версий. |
| `flatten` | Привести раскладку файлов архива к текущему формату. |

Типичные сценарии:

```powershell
# Фото, видео или всё сразу
.\run.bat scan --media all
.\run.bat download --media all --workers 8 --read-timeout 30 --attempts 3

# Проверка целостности без сети
.\run.bat verify --media all
.\run.bat status --media all

# Повторить только то, что не скачалось
.\run.bat download --media photo --only-missing
```

`Ctrl+C` останавливает выдачу новых файлов: текущие загрузки завершаются, готовые
файлы сохраняются. Ошибки серверов Яндекса обычно временные, поэтому достаточно
повторить `download` позже.

Коды выхода: `0` — всё скачано и проверено, `2` — есть ошибки, файлы в очереди
или незавершённый scan, `130` — прервано пользователем.

## Параметры

| Параметр | Значения | По умолчанию | Описание |
| --- | --- | --- | --- |
| `--media` | `photo` \| `video` \| `all` | `photo` | Тип медиа |
| `--workers` | `1..32` | `4` | Число параллельных загрузок |
| `--attempts` | `1..8` | `4` | Число попыток на файл |
| `--read-timeout` | секунды | `30` | Таймаут чтения оригинала |
| `--limit` | `N` | — | Скачать не больше N файлов за запуск |
| `--order` | `path` \| `reverse` \| `size` \| `spread` | `path` | Порядок выборки: по пути, с конца, сначала небольшие, из разных частей каталога |
| `--dates` | `cloud` \| `none` | `cloud` | Переносить облачные даты на файлы |
| `--only-missing` | — | — | Повторить только failed/deferred |
| `--no-previews` | — | — | Не сохранять превью, если оригинал недоступен |
| `--source` | `list` \| `photoslice` | `list` | Источник списка при сканировании |
| `--color` | `auto` \| `always` \| `never` | `auto` | Цвета в консоли: `auto` включает их только в интерактивном терминале |
| `--output` | путь | `backup` | Каталог архива |
| `--cookies` | путь | `cookies.json` | Файл cookies |

> Порядок `path` повторяет порядок облачных путей и не гарантирует хронологию.
> На Unix переносится только mtime. Дату создания файла можно установить только в Windows.

**Консольная панель.** Сверху показывается общий прогресс и счётчики «Успешно →
Превью → Ошибок», под ними строки воркеров W01–W32. Цвета означают:
зелёный — оригинал сохранён, жёлтый — сохранено превью или оригинал недоступен,
красный — техническая ошибка, серый — ожидание. Если окно слишком низкое, панель
показывает число скрытых воркеров. Файл `console.log` всегда пишется без ANSI-кодов.

## Превью вместо оригиналов

Иногда Яндекс не отдаёт оригинал. Тогда YaPhoto сохраняет лучшее доступное превью
в отдельную папку `previews`, а в галерее такие файлы отмечены золотой рамкой.
Превью не заменяет оригинал: его размер ограничен тем, что возвращает Яндекс, а
метки XL/XXXL обозначают доступные варианты, а не гарантированное разрешение.

Попытки скачать оригинал повторяются при каждом следующем `download`. После
успешной проверки оригинала связанное превью удаляется.

```powershell
.\run.bat rescue-previews --media photo
.\run.bat upgrade-previews --media photo
```

## Целостность и статусы

| Статус | Значение |
| --- | --- |
| `verified` | Размер и облачный MD5 совпали |
| `downloaded` | Облачного MD5 нет; файл сохранён, локальный SHA256 записан |
| `pending` | В очереди |
| `deferred` / `failed` | Отложен или не скачан; повторяется при следующем запуске |

Повторный `download` выполняет **быструю проверку**: если размер, mtime и ctime
проверенной копии не изменились, содержимое заново не хешируется. Изменённые
файлы и старые записи без сохранённых признаков проверяются полностью. Для
большого архива из ранних версий это может занять один долгий проход.

Быстрая проверка не заменяет полную. Периодически запускайте `verify`, а также
после ручного удаления или изменения файлов в архиве.

## Настройки и структура архива

По умолчанию архив хранится в `backup/`, а cookies берутся из `cookies.json`. Чтобы
указать другие пути, создайте `local.json` по образцу `local.example.json`
(этот файл в `.gitignore`):

```json
{ "output": "D:/Archives/YaPhoto", "cookies": "D:/Private/cookies.json" }
```

Относительные пути считаются от каталога проекта. Конфиг читают и CLI, и
веб-интерфейс, но явные `--output` и `--cookies` имеют приоритет. Каталог привязан
к аккаунту и абсолютному пути архива, поэтому не переносите базу вручную.

```
backup/
├── photos/                 # оригиналы фото
├── videos/                 # оригиналы видео
├── previews/               # превью для недоступных оригиналов
├── catalog.sqlite3         # каталог и статусы
├── _partial/               # недокачанные части
├── _metadata/              # служебные метаданные
├── _thumbnails/            # кэш миниатюр галереи
├── console.log             # журнал (5 МиБ + 3 архивных файла)
├── server_stats.txt/.json  # статистика серверов хранения
├── report_<media>.json             # сводка
├── errors_<media>.json             # ошибки без превью
├── missing_originals_<media>.json  # все записи без оригинала (с флагом has_preview)
└── previews_<media>.json
```

Если появляется сообщение «Архив уже занят другим процессом», дождитесь окончания
текущей команды или остановите её (`Ctrl+C` или кнопка ■ в галерее). Удалять
`.export.lock` не нужно: блокировку снимает операционная система.

## Безопасность

- Cookies и `local.json` хранятся только локально и исключены из Git.
- Веб-сервер слушает только loopback, все страницы и API требуют сеанса. Сеанс
  выдаётся как HttpOnly-cookie с `SameSite=Strict`, изменяющие запросы требуют
  CSRF-токен, включена строгая CSP без inline-скриптов. Можно также передавать
  `Authorization: Bearer <секрет>`.
- Ссылку входа с `?key=…` не публикуйте: она может остаться в истории браузера и
  в выводе терминала. Перезапуск сервера отзывает ключ.
- HTTP без TLS предназначен только для `127.0.0.1`, не открывайте сервер в сеть.

Если cookies всё же попали в публичный репозиторий, завершите сессию Яндекса и
очистите историю Git. Полная политика описана в [SECURITY.md](SECURITY.md).
